# FAQ

## Почему не PassWall 2 / Home Proxy?

PassWall — отличный инструмент, но под другие задачи и другую аудиторию:

| | PassWall 2 | Морок |
|---|---|---|
| Интерфейс | простыня форм, экспертный | современный дашборд, сайдбар, группы |
| Оптимизация доставки пакетов | нет | zapret2/nfqws2 из коробки, адаптивные профили фрагментации |
| Fallback | базовый | цепочки нод с urltest + kill switch (kill/direct/nothing) |
| Бинари движков | зависимости из чужих фидов | вендорные, внутри пакета, свой канал обновлений |
| Per-device маршрутизация | ограниченная | по MAC из списка DHCP-клиентов, одной кнопкой |
| Прозрачность | логи в syslog | журнал решений + метрики + диагностика в UI |

Морок делался под принцип «поставил и забыл»: правила маршрутизации и
профили оптимизации настраиваются один раз — и работают для всех
устройств в сети.

## Это VPN?

Нет. Это прозрачная маршрутизация на роутере: трафик выборочно (по
правилам) уходит через твои ноды (vless/trojan/hy2/…) или обрабатывается
движком оптимизации доставки пакетов. Ноды/подписку ты приносишь свою —
Морок не продаёт и не раздаёт серверы.

## Какие протоколы поддерживаются?

VLESS (включая Reality, xhttp), VMess, Trojan, Shadowsocks, Hysteria2,
TUIC, AmneziaWG (при наличии kmod-amneziawg). Два ядра на выбор:
sing-box (по умолчанию) и xray (нужен для xhttp).

## Работает ли установка и обновления при недоступном GitHub?

Да. Манифесты канала и install.sh раздаются через jsdelivr
(`cdn.jsdelivr.net`). Сами пакеты и бинари лежат в GitHub
release-ассетах; если GitHub из твоей сети недоступен — первичную
установку делай офлайн-вариантом (см. docs/install-*.md), а дальнейшие
обновления бинарей сами уйдут через туннель (bin_update.sh умеет фоллбэк
на 127.0.0.1:7890).

## Сколько ресурсов ест?

~64 МБ флеша (вендорные бинари), в работе 60–120 МБ RAM в зависимости от
числа rule-sets. Логи и состояние — в tmpfs, флеш не деградирует.

## Безопасно ли? Есть ли телеметрия?

Телеметрии нет. Весь код открыт (GPL-3.0), ubus-API ограничен ACL,
убиваемых процессов/стучалок нет. Вендорные бинари — официальные релизы
апстримов, sha256 сверены и задокументированы в
`luci-app-morok/binaries/VERSIONS`. Опциональная телеметрия обсуждается
отдельно и будет только opt-in.

## Что если все ноды умерли?

Fallback-сторож переключит на следующую живую из цепочки. Если живых нет —
сработает kill switch по твоему выбору: «kill» (перекрыть трафик — ничего
не утечёт мимо), «direct» (пустить напрямую) или «nothing».

## Помогает ли при деградации доставки до видеохостингов?

Да — правилом с action=antidpi и профилем стратегии (профиль universal
проверен у ряда провайдеров). Если доставка до отдельных CDN режется по
SNI на уровне DPI-фильтрации провайдера, это компенсируется тем, что
трафик можно завернуть в туннель тем же правилом (адаптивный режим сам
подбирает рабочий путь).

## Как обновить приложение?

Той же командой, что и установка: install.sh возьмёт свежий релиз из
канала. Конфиг, ноды и списки сохраняются. Автообновление приложения из UI
— в роадмапе.

## Где логи и диагностика?

LuCI → Services → Морок → «Журнал» (решения guardian, подписки,
переключения) и «Диагностика» (поэтапная проверка: сервис → конфиг →
туннель → DNS → доставка пакетов) с кнопками «исправить».

## Есть ли готовые списки доменов?

Да — есть готовые пресеты списков (YouTube, Discord, Meta и др.) +
списки сообщества re:filter (~81k доменов) + geosite/geoip rule-sets +
кастомные правила. Маркет кураторских пресетов — в роадмапе.
